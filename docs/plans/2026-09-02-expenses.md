# Expenses and Financial Control Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add native expense tracking and currency-separated projected/actual cash flow to KazeOS without rebuilding or destabilizing the existing charges, payments, services, dashboard, or mobile experience.

**Architecture:** Introduce a bounded expenses domain with three owner-scoped Drizzle tables, while sharing the existing money, commercial-date, recurrence, authenticated-transaction, form-control, responsive-ledger, and dashboard patterns. Expenses store one final payment directly; recurring templates generate three months of idempotent occurrences, and SQL aggregates feed pure currency-map helpers for projected and actual cash flow.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript 6, Supabase Auth/PostgreSQL, Drizzle ORM/Kit, Zod, Vitest, Testing Library, Playwright, Tailwind CSS, Lucide.

```ts
export type PersistedExpenseStatus = "planned" | "pending" | "paid" | "cancelled";
export type ExpenseStatus = PersistedExpenseStatus | "overdue";

export function getExpenseStatus(expense: {
  dueDate: string;
  status: PersistedExpenseStatus;
}, today: string): ExpenseStatus {
  validateCommercialDate(expense.dueDate);
  validateCommercialDate(today);
  if (expense.status === "paid" || expense.status === "cancelled") return expense.status;
  return compareCommercialDates(expense.dueDate, today) < 0 ? "overdue" : expense.status;
}
```

## Implementation sequence rationale

This order minimizes rework:

1. schema and invariants first;
2. shared recurrence/status/money rules second;
3. mutations and idempotency before UI;
4. reusable aggregate queries before cards/charts;
5. one expense form and one responsive ledger built from existing controls;
6. Dashboard integration only after financial definitions are proven;
7. seed, browser acceptance and full regression last.

It avoids a general ledger rewrite, avoids duplicated recurrence code and keeps every intermediate commit testable and reversible.
